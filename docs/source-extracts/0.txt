  1. Project ka idea — hum kya bana rahe hain?
  Sustain-X-Ray ek campus-focused platform hai jo university ki electricity aur water consumption ko ek jagah monitor
  karega. System unusual usage ko flag karega, possible reasons evidence ke saath dikhayega, corrective actions suggest
  karega aur action ke baad check karega ki usage ya cost mein actual improvement aaya ya nahi.

  Hamari core approach: Measure → Detect → Explain → Act → Verify. Sirf graph dikhana goal nahi hai; data ko practical
  campus action aur measured result se connect karna goal hai.

    Stage                        System kya karega?

    Measure                      Electricity bills/smart meter readings aur RO/block water readings collect karega.

    Detect                       Baseline ke comparison mein unusual spikes, night usage ya water-balance gaps flag karega.

    Explain                      Possible causes aur supporting evidence dikhayega; cause ko fact tabhi bolega jab evidence ho.

    Act                          Recommended checks, maintenance ticket aur responsible person assign karne ka workflow.

    Verify                       Action ke pehle/baad comparable data dekhkar saving ko verified, estimated ya inconclusive label
                                 karega.

  Current reality
  • Electricity: June, July aur August 2026 ke university-wide NPCL bills available hain.
  • Water: RO logbook readings discuss hui hain; flow/rejected flow litres mein hain, lekin readings ka time interval/cumulative
  nature confirm karna hai.
  • Lab-wise electricity: abhi individual lab readings confirm nahi hui hain. University-wide bill se lab-specific wastage identify
  nahi kiya ja sakta.
  • Live data: compatible meter interface/gateway ya sensors confirm hone ke baad hi automatic monitoring possible hogi.

  6. Kitni savings possible ho sakti hai?
  Neeche ke numbers illustrative scenarios hain: uploaded bills mein total monthly bill roughly ■2.22 crore–■3.05 crore raha.
  Hum us range par percentage apply karke scale samajh rahe hain. Yeh actual forecast, guaranteed saving ya measured
  result nahi hai.

    Scenario                                 Illustrative monthly amount                         Annualized equivalent*

    2% reduction                             ■4.44–6.11 lakh                                     ■0.53–0.73 crore

    5% reduction                             ■11.11–15.27 lakh                                   ■1.33–1.83 crore

    10% reduction                            ■22.21–30.55 lakh                                   ■2.67–3.67 crore

  *Annualized equivalent monthly range ko 12 se multiply karta hai. Seasonality, fixed demand charges, tariff changes aur bill ke components ka effect is
  calculation mein model nahi hua.

  Savings ka claim kaise prove hoga?
  1. Pehle comparable time window ka baseline set karenge.
  2. System unusual usage detect karega aur staff action lega.
  3. Action ke baad same type ke comparable period ka consumption dekhenge.
  4. Occupancy, weather, hours ya tariff jaise changes ko note karenge.
  5. Evidence sufficient hua toh saving verified; warna estimated ya inconclusive label hogi.

  Measured kWh saving = adjusted baseline kWh − post-action actual kWh. Financial saving ko applicable marginal energy
  rate aur demand-charge effects ko dhyan mein rakhkar calculate karna chahiye.

  Water savings ka rupee estimate abhi nahi dena chahiye, kyunki reliable water consumption/cost totals aur reading intervals
  confirm nahi hain. Pehle RO input, output, reject aur block readings ko validate karenge.

  7. Water module: formulas aur examples
  Har water reading ke saath unit, timestamp aur interval zaroor store karenge. Agar logbook cumulative meter reading hai
  toh per-day use nikalne ke liye successive readings ka difference lenge; agar readings interval totals hain toh unhe directly
  same interval ke saath compare karenge.

            WATER INPUT = PRODUCT / USABLE OUTPUT + REJECTED WATER + BALANCE DIFFERENCE


  RO rejection rate = rejected water ÷ input water × 100%
  RO recovery rate = usable output ÷ input water × 100%
  Water balance difference = input − usable output − rejected water

  Agar difference aata hai toh iska matlab automatically leak nahi. Timing mismatch, tank level change, unmetered branches
  ya sensor error bhi reason ho sakte hain.

  Proposed measurement points
    Point                           Data/use                                 Dependency

    RO input                        Total feed water                         Flow meter or validated logbook reading.

    RO usable output                Usable production                        Product-flow measurement.

    RO rejected flow                Reject volume and rejection ratio        Confirm reading interval and process arrangement.

    Block 1/2/3                     Block-wise water use                     Block inlet meter(s) and pipe map.

  Optional future sensors: TDS, pressure, tank level. Inko tab add karna jab use-case aur compatible sensor interface confirm
  ho.

  14. Risks, validation aur success metrics
  Important checks before live launch
  • Electricity bill periods, meter multiplier, units, tariff components aur available interval exports verify karo.

  • RO logbook mein readings per hour/day/inspection hain ya cumulative—confirm karo.

  • Water readings ko same interval aur units mein compare karo; tank-level change ko consider karo.

  • Occupancy, academic calendar, operating hours, weather aur equipment changes ko possible context ke roop mein record
  karo.

  • Configurable thresholds aur human review se start karo; real data par false alerts tune karo.

  • Role-based access, secure API secrets, Firestore rules, audit trail aur backups implement karo.

  • Har alert ke liye responsible team/owner aur closure workflow define karo.

  • Savings ko verified tabhi bolo jab baseline aur post-action data comparable aur sufficiently complete ho.

  • Data completeness and freshness.
  • Alert precision after human review (kitne alerts genuinely actionable the).
  • Time from alert to review and resolution.
  • Number of completed corrective actions.
  • Verified kWh and water-volume reduction.
  • Verified financial savings, separately from estimated savings.
  • False-positive rate and unresolved data-quality issues.




  Final summary
  Sustain-X-Ray ka goal campus resource data ko actionable decisions aur measurable improvements mein badalna hai.
  Available bills overall electricity trend ki shuruaat dete hain; lab/building-level diagnosis aur reliable savings claims ke liye
  granular data, validated baseline, corrective action aur post-action measurement chahiye.
  Source/assumption note: Electricity figures wohi values hain jo uploaded NPCL bills ke page 1 se pehle discussion mein transcribe ki gayi thi. Final
  implementation se pehle original PDFs se figures aur billing periods dobara verify karna best rahega. Water, meter connectivity aur hardware budget
  abhi preliminary hain.
